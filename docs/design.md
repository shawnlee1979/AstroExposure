# 天文摄影曝光参数推荐 App — 设计方案 v1.0（定稿）

- 定位：本文件为 v1.0 开发的设计基线；变更须经第 11 节决议记录登记后生效。
- 版本沿革：v0.1 初稿 → v0.2（漂移实测口径、离线光害、严苛三档、月光入算四项口径落实，目标分类重构为五类，新增当日最佳目标库与开源选型）→ v0.3 定稿（其余决议全部落实）。逐条决议见第 11 节。
- 目标用户：面向个人天文摄影的单人使用场景。相机库首批收录 Sony A1 II 与 ZV-E1，跟踪档案以 Benro Polaris Pro 为参考机型；典型拍摄为 50mm 及更广、f/1.4–2.8 的带地景星野与广域星空，兼顾深空入门、月 / 日食与流星雨。
- 平台：Android 原生，侧载安装，全离线。
- 一句话定位：**在开拍前 30 秒内，针对「今晚、此地、这台相机 + 这支镜头、这个目标、这种跟踪条件」，给出一组可以直接拨到相机上的曝光起步参数（光圈 / 快门 / ISO），并说清为什么、上下包围各留多少。**

> 产品立场（写死在产品里，不是口号）：所有推荐值都是**起步值**，不是「正确曝光」。界面上每张参数卡片都固定带一行小字：「起步值 — 请以直方图与试拍为准，亮部不溢出优先。」理由见第 10 节风险与限制。

## 1. 产品定位与边界

### 1.1 做什么

1. **曝光推荐**：按位置（经纬度）、日期时间、相机、镜头、跟踪档案、环境（天光 = 离线光害图谱 + 月光贡献）与目标类型（五类，见 2.7），计算推荐光圈 / 快门 / ISO，给出 ± 包围建议与一句话理由。
2. **当晚天象速览**：日落 / 天文暮光起止、天文夜时长、月出月落、月相与照明比、目标（或银心、流星雨辐射点）的高度角曲线与最佳拍摄窗口。这些信息直接参与曝光计算（例如月光贡献、目标赤纬、目标过中天时刻），不是装饰。
3. **今晚最佳概览**：按当日日期 + GPS 地点，跨类别列出今晚最值得拍的少数目标与事件（完整目标库与评分引擎见第 6 节，分期见第 9 节）。
4. **计划保存**：把一次推荐连同全部输入存为一条「拍摄计划」，可导出纯文本，在野外断网时也能回看。

### 1.2 不做什么（明确排除，防止范围膨胀）

| 不做 | 原因 / 替代 |
|---|---|
| 不控制云台（不发送任何云台控制命令） | 与任何云台控制 App 无依赖关系；本 App 只做曝光与时机的计算 |
| 不控制相机（不做遥控快门、不用 USB / Wi-Fi 联机） | 相机控制涉及 Sony SDK / 协议与机型适配，成本与收益完全不成比例；用户用快门线 / 机身间隔拍摄即可 |
| 不做后期处理（不叠加、不降噪、不拉伸） | 后期在电脑端已有成熟工具（用户既有摄影后期工作流） |
| 不做星图 / 找星（无星图渲染、无 GOTO） | 已有 Stellarium 等现成工具；本 App 只算「曝光」与「时机」 |
| 不做云端同步、无账号、无联网功能 | 野外无网络是常态；隐私与可靠性都要求本地优先 |
| 不替代专业日食安全指南 | 日食模块只给参数参考与强制安全闸门（见 5.4.2），安全规范以 NASA / AAS 等权威指南为准 |

### 1.3 与外部环节的关系

- **与云台控制软件：无依赖关系。** 本 App 独立包名、独立签名密钥（见 8.5），不读写任何云台控制 App 的数据；与任何云台控制 App 无依赖关系，对方停用或更换版本不影响本 App，反之亦然。
- **与基线实测：单向数据输入关系。** 先明确口径：**漂移率（″/min）是「云台 + 校准质量」的属性，不随相机、镜头变化**；随组合变化的只是把角漂移换算成像素位移后的「像素容忍时长」，由 App 按当前相机像素间距与镜头焦距现算（见 5.2.2）。因此实测只需**按校准档位各测一次**（单星一档、双星一档），且用**最严苛组合（A1 II + 50mm，像素最小、最先拖线）**执行——测得的漂移率用于其他组合时结论只会更宽松，不必逐组合重测。基线实测清单的近 / 远双目标安排正好给出每档的「典型漂移」与「最差漂移」两个数，连同漂移形态（线性 / 周期）录入跟踪档案（见 2.5）。也就是说，实测报告是本 App 跟踪模型的**数据来源**，本 App 是实测数据的**消费端**。在实测数据到位之前，跟踪档案**留空**（不预置任何估计漂移率，跟踪卡片只给换算关系与公式说明，见 2.5 / 2.8 / 5.2.2），实测到位后录入并保留测量条件与日期以便对比。
- **与此前那张 50mm 曝光速查表：** 速查表是本 App 计算结果的一个静态切片；本 App 上线后速查表退役，数值口径以本 App 引擎为准（两者若不一致，以引擎的完整公式为准，并在本文件第 5 节注明口径差异来源）。

### 1.4 典型使用场景（验收时按此走查）

1. **出发前（有网也行、无网也行）**：选地点（收藏地点或 GPS，光害由内置离线图谱按坐标自动带出）、日期，先看「今晚最佳概览」决定拍什么；再选相机 + 镜头 + 目标「广域星空（跟踪）」，看当晚时间线：天文夜几点开始、银心几点过中天、月亮几点升起、月光干扰何时最弱；保存为今晚计划。
2. **现场架设后**：打开计划，参数卡片给出「50mm、f/2、60s、ISO 800（A1 II / Polaris 单星档案 / 标准档）」与包围档；照此试拍一张，看直方图微调。
3. **换目标**：同一夜从广域星空改拍月亮，切换目标类型即可，历算（月相、月亮高度）自动带入，不需要重新输入任何东西。

## 2. 输入层设计

设计原则：**能自动的绝不手输；手输的给默认值；缺失时降级而不是报错。** 每个输入项按下表定义：来源 / 默认值 / 缺失或异常时的降级。

### 2.1 位置（经纬度、海拔可选）

| 项 | 设计 |
|---|---|
| 来源（三选一） | ①GPS 自动定位（进入 App 时若有权限则刷新）；②手动输入经纬度（十进制度，带正负号说明与示例）；③收藏地点列表（名称 + 经纬度 + 海拔 + 光害手动 Bortle 覆盖值（可选，见 2.6），本地增删改） |
| 默认值 | 上次使用的地点；首次启动无默认，必须选一次（可用 GPS 一键获取） |
| 精度要求 | 历算对位置不敏感：经纬度误差 0.1° 只影响日月出没时刻约 ±1 分钟量级；GPS 的米级精度绰绰有余，手输到小数点后 2 位即可 |
| 降级 | 无定位权限且未手输 → 历算与时间线功能禁用并明示原因，但纯曝光计算（月亮 Looney 11、NPF 等不依赖位置的部分）仍可用 |
| 备注 | 海拔仅用于地平线 / 大气消光的粗修正（低高度目标），MVP 可只记录不参与计算，字段先留 |

### 2.2 日期与时间

- 默认「今晚」：以当地时间定义——若当前在白天，取即将到来的夜晚；若在凌晨，取正在进行的夜晚（以日落为界，而非 0 点）。
- 可任意选日期（查未来某晚的月相与天文夜，或为日食预演）。
- 内部一律用 UTC 计算；**显示时区按所选地点坐标查定**（口径见 UI 设计规格 7.6，0.4.0 起执行），与设备时区不一致时在今晚页明示。早期「按设备时区显示、假设设备时区 = 地点时区」的口径已被取代，变更登记见第 11 节补充行。
- **时间健康检查（进 v1.0）**：旅行时手机一般开启网络时间同步，时钟本身通常可信——App 的职责是**提醒用户检查**，而不是自行纠时或假装无事。检查时机：每次打开 App、以及每次生成计划时各检一次。触发条件（任一命中即提醒）：(a) 系统时区与所选地点的时区不一致；(b) 能取得 GPS 时间、且 GPS 时间与系统时间偏差超过 60 秒。命中时弹出明确提醒：「检测到设备时钟 / 时区可能不一致——请确认已开启网络时间自动同步、且时区正确；本 App 的全部历算以设备时钟为准。」不命中不打扰、不留痕。历算侧的时间源依赖说明见 4.1。
- 时间精度：用户只能选到日；具体时刻由历算给出（暮光、过中天等到分钟）。

### 2.3 相机（设备库）

- 内置首批两台：**Sony A1 II（ILCE-1M2）**、**Sony ZV-E1**，数据见第 3 节。
- 数据模型字段：名称、画幅宽 × 高（mm）、有效分辨率（宽 × 高 px）、像素间距（由前两项计算生成，不单独手填，防口径不一致）、原生 ISO 范围、双增益切换点（分机械 / 电子快门，如适用）、读出噪声表（ISO → e⁻，可为空，见 3.4）、满阱量级（e⁻，可为空）、量子效率参考值（可为空）。
- 支持用户新增自定义相机（只填画幅与分辨率即可用大部分功能；读噪缺失时深空子曝光降级，见 2.8）。
- 默认：上次使用的相机。

### 2.4 镜头（镜头库）

- 字段：名称、焦距（mm，定焦单值；变焦填范围且使用时选当前焦距）、最大光圈、常用光圈档（默认 = 最大光圈、收 1 档、收 2 档、f/8、f/11 五个候选，推荐引擎按目标类型从中选，见第 5 节各模型）。
- **内置清单**：内置五家无反镜头清单——Sony（E 卡口）、Canon（RF）、Nikon（Z）、Tamron、Sigma，条目字段：型号、焦距（定焦单值 / 变焦段）、最大光圈、卡口。收录范围以天文常用为主：**广角与快速定焦优先收齐**，长焦与冷门型号可不全；清单在构建期整理、随 App 版本更新。
- **用户自定义创建**：其余品牌、老镜头、转接镜头一律在 App 内自建，表单字段：名称、焦距或变焦段、最大光圈，可选：重量、滤镜口径。实际镜头从内置清单选取或自建即可。
- 降级：未建镜头条目时，可临时手输焦距与光圈一次性计算，不强制建库。

### 2.5 跟踪档案（本 App 与实测线的接口，最重要的一组输入）

**实测口径（先明确，再谈字段）**：漂移率（″/min）是「云台 + 校准质量」的属性，**不随相机、镜头变化**，档案里不按焦距、不按机身分存多组；随组合变化的是像素容忍时长，由计算层按当前像素间距与焦距现算（见 5.2.2）。实测规程与之对齐：

- 每个校准档位只测一次（单星一档、双星一档），用**最严苛组合 A1 II + 50mm** 执行基线实测（像素最小、最先拖线；该组合测得的漂移率用于 ZV-E1 或更短焦距时，像素容忍只会更宽松）；
- 基线实测的近 / 远双目标安排给出两个代表值：典型工况目标的读数记为「典型漂移」，远目标 / 最差工况的读数记为「最差漂移」，两值都进档案；
- 严苛档位与漂移的衔接（见第 5 节通则一）：**严格档用最差漂移算，标准 / 宽松档用典型漂移算**。

每条 tracked 档案字段：名称、类型、**典型漂移（″/min）**、**最差漂移（″/min）**、漂移形态（线性 / 含周期误差）、**测量条件备注（机身 / 镜头 / 目标 / 日期）**、备注。

| 档案（预置） | 类型 | 典型 / 最差漂移 | 说明 |
|---|---|---|---|
| 不跟踪（固定三脚架） | untracked | —（用地球自转，见 5.2.1 NPF） | 广域 / 流星雨的默认对照组 |
| Polaris 单星校准 | tracked | 待基线实测填入 | 测量条件固定为 A1 II + 50mm、近 / 远双目标；当前经验描述「50mm 约可稳定跟踪 1 分钟」**不是**漂移率，禁止直接换算录入，须以实测报告的 ″/min 为准；实测到位前**留空**（不预置任何估计值，界面标注「待基线实测录入」，见 2.8 / 5.2.2） |
| Polaris 双星校准 | tracked | 待双星实测后新建 | 目标状态（期望稳定 2–3 分钟），实测前不预置数值、不预置档案数值，避免把愿望当数据 |
| 自定义 | tracked | 用户手输 ″/min（典型必填，最差可空，空则等于典型） | 换云台后复用 |

- 漂移形态若实测给出，记录之；MVP 计算只用线性分量，周期分量仅在理由文案中提示「周期摆动明显时请在严格档取值」。
- 档案更新纪律：新实测覆盖旧值时保留旧值与测量日期于备注，形成漂移的历史序列（同一台云台的漂移随季节 / 负载变化时可回看）。

### 2.6 环境（天光）

**主路径：GPS 坐标 → 查内置离线光害数据集，全程不联网。** App 内置一份基于 VIIRS 卫星数据的全球夜空亮度图谱（Falchi 等《The New World Atlas of Artificial Night Sky Brightness》一类公开数据，选型与许可见 8.3）在构建期降采样成的网格；运行时按坐标查得该点天光亮度（人工亮度 mcd/m² 或 mpsas，含自然底的口径在数据集元信息里写死），再换算为 Bortle 估计供界面显示与分档引用。数据随 App 版本更新（发新版 APK 时替换网格），**不是在线缓存、不存在运行时下载**。

| 项 | 设计 |
|---|---|
| 光害基线（主） | 坐标 → 离线图谱查表：输出天光亮度（mpsas）与 Bortle 估计；卡片与理由中标注「图谱估算」 |
| 数据体积控制 | 原始图谱为 30 角秒网格、GB 级，不可能整包进 APK。构建期重采样策略：**全球粗网格（约 5 角分）保底 + 北美与常用地区细网格（约 2 角分）**，亮度值量化编码、仅保留陆地像元；量级估算合计约 10–30MB（工程估算，开发期实测验证，超预算时先砍全球粗网格分辨率）。取舍理由：查某地 Bortle 估计不需要角秒级精度，2–5 角分（约 2–8 km）与光害的实际空间变化尺度匹配 |
| 误差声明 | 图谱值是卫星数据 + 大气传播模型的**建模值**，且数据年份偏旧（Falchi 图谱基于 2016 年前后 VIIRS 数据，城市扩张区系统性偏暗）；不含当晚实况变量（湿度、气溶胶、云层反照、积雪、邻里灯光开关）。结论：图谱值就是本 App 的默认与主要依据——**无 SQM 等光害测量工具，不做实测修正**；建模偏差由推荐值的包围与保守档位吸收。用户凭经验可在收藏地点手填 Bortle 覆盖值（见下行），填了则标注「手动覆盖」 |
| Bortle 手动覆盖（可选兜底） | 不要求任何测量工具：用户凭经验为收藏地点（或全局）手填一个 Bortle 值，填了优先于图谱查值，卡片标注「手动覆盖」；这是唯一的覆盖通道，不填则全程图谱值。*未来候选（v1.x，仅登记一句）*：基于试拍照片背景值反推天光的照片标定法——无测量工具时唯一可落地的现场标定路径，本版不做 |
| Bortle 手选（图谱缺失时的兜底） | 仅在图谱查不到（网格缺失 / 海洋点）时出现：手选 1–9（带每级的中文特征描述辅助判断，如「Bortle 5：银河在头顶隐约可见、光害穹明显」）；用户主动覆盖走上一行「手动覆盖」通道。**不是默认输入路径** |
| 月光贡献 | **不手输、不单列**：由月光贡献模型（第 5 节通则二）定量算出并与光害基线合成「总天光」后参与各模型；界面同时给出月光干扰 强 / 中 / 弱 / 无的定性标注供速读 |
| 降级 | 无坐标且未手选 Bortle → 深空模型只给「达到 swamp 所需的背景电子数」而不给具体秒数，并提示补坐标或手选后可换算（见 2.8） |

### 2.7 目标选择（五类）

目标类型是输入层的最后一个选择，五类与第 5 节模型一一对应：

| 类别 | 子情形 / 附加输入 | 对应模型 |
|---|---|---|
| ① 带地景的星野 | 天空子情形：不跟踪 / 跟踪（随跟踪档案）；地景拍法：蓝调时刻 / 夜间长曝 / 高 ISO 多张（可多选，输出对应参数段） | 5.1（双套参数） |
| ② 广域星空 | 不跟踪 / 跟踪由跟踪档案决定，不在此重复选；可指定目标（银心 / 指定 RA·Dec / 星座级构图） | 5.2.1 / 5.2.2 |
| ③ 深空目标 | 目标名（记录用）或从目标库选（v1.1 起，见第 6 节）；总时长分档按目标类型 | 5.3 |
| ④ 月 / 日食 | 子模型二选一：月亮本体 / 日食（日食再选食分类型与所处阶段） | 5.4.1 / 5.4.2 |
| ⑤ 流星雨 | 从内置流星雨表选一场（或选「任意夜晚的散发流星」只给通用连拍参数）；连拍总时长 | 5.5 |

- 入口不止一处：可从分类列表选，也可从第 6 节「今晚最佳」榜单点选目标直接带入（类别与目标参数预填好，用户只核对设备与档位）。
- 类别互斥的是**输出结构**（如地景类出双套参数、流星雨类出连拍计划），不是输入负担：切换类别不清空已填的地点 / 设备 / 档位。

### 2.8 输入缺失时的降级总表（实现时逐项对照）

| 缺失项 | 受影响功能 | 降级行为 |
|---|---|---|
| 位置 | 历算、时间线、月光评估 | 禁用并明示；纯曝光公式照常 |
| 相机读噪表为空 | 深空子曝光秒数 | 给目标背景电子数（C·RN² 无法算则给方法说明）+ 提示「该机型读噪待补」；不给秒数，**绝不用别台机器的读噪冒充** |
| 光害数据不可用（无坐标、图谱缺该点、又未手填 Bortle 覆盖） | 深空子曝光、广域 ISO 建议 | 子曝光只给公式与查表路径；ISO 建议给宽区间并标注不确定性大 |
| 光害只有图谱值、无手动覆盖 | 全部以总天光为输入的模型 | 正常计算，卡片角标「天光为图谱估算」——此为常态而非降级（无光害测量工具，图谱值即依据）；用户手填 Bortle 覆盖后角标改为「手动覆盖」 |
| 跟踪档案漂移率未实测（留空） | 跟踪最长单张 | **不给具体秒数**：跟踪卡片只给换算关系与公式说明，并标注「待基线实测录入」；实测录入典型 / 最差双值后恢复秒数输出、角标消失 |
| 目标赤纬未知（广域类） | NPF 赤纬修正 | 用银心赤纬 −29° 或目标默认赤纬并在理由中写明所用赤纬 |

### 3.1 基础参数表

| 参数 | Sony A1 II（ILCE-1M2） | Sony ZV-E1 | 标注 |
|---|---|---|---|
| 传感器 | 35mm 全画幅堆栈式 Exmor RS CMOS | 35mm 全画幅背照式 Exmor R CMOS（与 A7S III / FX3 同系 12MP 传感器） | 【官】 |
| 画幅尺寸 | 35.9 × 24.0 mm | 35.6 × 23.8 mm | 【官】（B&H / Adorama 规格页与官方一致） |
| 有效分辨率 | 8640 × 5760（有效 50.1MP，总 50.5MP） | 4240 × 2832（有效 12.1MP，总 12.9MP） | 【官】 |
| 原生 ISO（照片） | 100–32000（扩展 50–102400） | 80–102400（扩展 40–409600） | 【官】 |
| 像素间距（计算值） | **≈ 4.16 µm** | **≈ 8.40 µm** | 【官】（由官方画幅与分辨率计算，口径见 3.2） |

### 3.2 像素间距的计算口径（写死，防止口径漂移）

```
像素间距 p (µm) = 画幅宽度 (mm) × 1000 / 水平有效像素数
A1 II： 35.9 × 1000 / 8640 = 4.155 µm → 取 4.16 µm
ZV-E1： 35.6 × 1000 / 4240 = 8.396 µm → 取 8.40 µm
纵向校验：A1 II 24.0×1000/5760 = 4.167 µm；ZV-E1 23.8×1000/2832 = 8.404 µm
```

- 纵横两向结果差 <0.3%，取横向值为准（行业惯例，NPF 与像元角尺度均用此值）。
- 注意：个别第三方数据库（如个别对比站）把 A1 一代的像素间距误植为 3.76µm（那是 61MP 的 A7R IV 的值），**本 App 不采信**；一切以「官方画幅 ÷ 官方分辨率」的自算口径为准。这正是本节要求写明口径的原因。

### 3.3 双增益（Dual Gain / HCG）切换点

| 机型 | 切换点 | 标注 |
|---|---|---|
| A1 II | **机械快门 ISO 640；电子快门 ISO 500**（一代 A1 为 500；二代机械快门上移至 640，电子快门维持 500） | 【测】PhotonsToPhotos 数据经 SonyAlphaRumors（2024-12-25）与 FredMiranda 实测帖转引；开发期以 PhotonsToPhotos 原图复核后转正 |
| ZV-E1（视频口径） | 标准色彩模式下第二增益约在 ISO 2000；S-Log3 双原生为 640 / 12800 | 【测】Photography Blog 评测与多家 FX3 / A7S III 同传感器评测（仅适用于视频 / Log 口径） |
| ZV-E1（照片口径） | **待核实** | 【待】照片模式的 HCG 切换点不能用视频口径冒充；开发期查 PhotonsToPhotos 的 ZV-E1 Read Noise 图逐点确认后录入。在补数前，ZV-E1 的深空 ISO 建议按「ISO 不变区间」保守给出（见 5.3） |

对产品的含义：深空与银河跟踪模式的 ISO 推荐将**优先落在切换点及其以上一档**（如 A1 II 机械快门 640 起步），因为切换点之后读噪显著下降且动态范围出现台阶式回升；低于切换点的高 ISO 段（如 A1 II 的 ISO 400）反而读噪更高，推荐引擎应主动避开并在理由中说明。

### 3.4 读出噪声随 ISO 的特征（定性 + 量级，逐点表待补）

两台机器的读噪曲线形态一致，均为典型的双增益「驼峰回落」形：

1. 基础 ISO 处读噪最高（现代 Sony 全画幅大致在 3–4 e⁻ 量级）；
2. 随 ISO 上升（LCG 段）读噪（以 e⁻ 计）下降；
3. 到 HCG 切换点出现阶跃式下降，落到 **约 1 e⁻ 量级**（同系参考：A1 一代在 HCG 段实测约 1.1 e⁻，A7S III 约 1.0 e⁻）；
4. 切换点以上继续缓慢下降并趋平，相机进入近似 ISO 不变（ISO-invariant）区间：此后再升 ISO 主要是放大而非减噪，推荐引擎据此给出「升到切换点即可，余下靠曝光时间」的建议。

**逐 ISO 读噪表（ISO 100 / 200 / 400 / 切换点 / 1600 / 3200 / 6400 …）目前状态为**：本次查证只有量级与切换点证据，没有可靠的逐点数值表。处理方式（写进开发任务）：从 PhotonsToPhotos Read Noise 图逐点读数 → 与 DXOMARK / sensorgen 类来源交叉 → 录入并标注来源与日期。在逐点表补齐前，深空模型对这两台机器使用「切换点处 RN ≈ 1.0–1.2 e⁻」的区间值计算，并把结果以区间呈现（见 5.3 的示例），不呈现伪精确的单点秒数。

### 3.5 满阱容量（Full Well）量级

| 机型 | 满阱（基础 ISO） | 标注 |
|---|---|---|
| A1 II | 约 4 万 e⁻ 量级（同系参考：A1 一代汇编值 39,898 e⁻） | 【待】A1 II 本机逐点值待 PhotonsToPhotos 数据复核；量级判断可信：4.16µm 像素、堆栈式，符合此类传感器约 35–45k e⁻ 的普遍区间 |
| ZV-E1 | 约 18–20 万 e⁻ 量级（同传感器 A7S III 汇编值 187,035 e⁻；另有讨论给出约 225k e⁻，两说并存） | 【待】两说差异约 20%，录入时以 PhotonsToPhotos 增益反推为准并注明 |

满阱在本 App 中的用途有限：主要用于深空模式提示「背景目标电子数占满阱比例」与「亮星饱和风险」，以及月亮 / 日食模式的高光余量提示；不参与核心推荐公式。因此量级精度足够，逐点精确值不阻塞 MVP。

### 3.6 两台机器的差异化影响（本节要点，引擎必须区别对待）

像素间距差约 2 倍（4.16 vs 8.40 µm），导致同一镜头下结论系统性不同：

| 维度 | A1 II（4.16µm） | ZV-E1（8.40µm） |
|---|---|---|
| 像元角尺度 @50mm（206.265 × p / f） | ≈ 17.1 ″/px | ≈ 34.7 ″/px |
| NPF 不跟踪最长快门 @50mm f/1.4、银心赤纬（完整式，见 5.2.1） | ≈ 2.0 s | ≈ 3.3 s |
| 同漂移率下跟踪可容忍时长（同 px 标准） | 基准 | 约 2 倍于 A1 II |
| 深空子曝光（同天光、同光圈） | 单像素集光慢 → 达 swamp 所需时间长；但 RN 同为 ~1 e⁻ 量级时，所需背景电子数相同，差异全在天光电子速率（像元面积差 4 倍 ⇒ 速率差约 4 倍 ⇒ 子曝光约 4 倍时长） | 大像元集光快，子曝光短；总时长相同时帧数多、单帧文件小（12MP） |
| 适用倾向（引擎文案口径） | 分辨率优先：适合后续裁切、接片单帧覆盖小但细节多 | 速度优先：广域星野「出片效率」高，对跟踪误差与对焦误差更宽容 |

引擎禁止对两台机器共用同一套默认 ISO / 快门：所有默认值必须由各自的相机记录派生。

## 4. 计算层一：天文历模块（集成 Astronomy Engine + 薄封装）

### 4.1 选型与自研范围

历算层**不再自研天文算法**：直接采用 **cosinekitty/astronomy（Astronomy Engine）的官方 Kotlin 版**（MIT 许可，单文件 `astronomy.kt`，经 JitPack 分发或直接纳入工程源码，选型细节与备选见 8.3）。Engine 以 ±1 角分为设计目标、与 NOVAS / JPL Horizons 对照测试过，本 App 所需的量它几乎全覆盖：

| 本 App 所需的量 | Engine 供给方式 |
|---|---|
| 太阳 / 月亮位置（赤道 / 地平坐标，可选折射修正） | `Equator` 系列函数直接给 |
| 日出日落、民用 / 航海 / 天文暮光起止 | 升落 / 暮光搜索函数直接给（高度角阈值口径与本 App 原设计一致） |
| 月相 / 照明比、月出 / 月落（含无月出 / 无月落日） | 月相函数（任意黄经差时刻、照明相关量）+ 月亮升落搜索 |
| 恒星时、任意目标（RA/Dec）高度 / 方位曲线、过中天 | `DefineStar` 定义自定义天体后，复用同一套地平换算与升落 / 中天搜索；采样间隔本 App 定为 5 分钟 |
| 银心窗口 | 银心以 RA 17h45m、Dec −29.0° 用 `DefineStar` 建为固定目标，窗口判定逻辑（升到 20°、过中天与最大高度、落下 20°、与天文夜 / 月光求交集）为本 App 封装层 |
| 星座归属（第 6 节星座库用） | `Constellation` 函数由坐标直接判定，省掉整套星座边界数据 |
| 日月食事件发现 | `SearchSolarEclipse` / `SearchLunarEclipse` 给**事件级**预报（何时、类型、全球最大食分）；本地接触时刻它给不了，见下 |

封装层（`ephemeris/` 包）只做三件事：①把 Engine 的类型与单位适配成本 App 的数据类（见 4.3 接口）；②补 Engine 不管的**窗口 / 交集判定**（最佳窗口 = 高度 >30° ∩ 天文夜 ∩ 低月光，阈值可配）；③目标高度 <10° 时打「低高度，消光与色差明显，参数仅供参考」标记。**自研保留项只有一件硬骨头**：日食在**用户所在地**的初亏 / 食甚 / 复圆时刻——Engine 只给事件级预报，该量需按 NASA 贝塞尔元素另行自算（含 ΔT 改正），排入 v1.1（见 5.4.2 与第 10 节风险登记）；commons-suncalc（Apache-2.0）仅作日月时刻的交叉校验备选，不作主引擎。

**时间源依赖（与 2.2 的「时间健康检查」互为表里）**：历算层的一切时刻输出以**设备时钟**为时间源——Engine 算得再准，时钟错 5 分钟，全部时刻输出等量平移。显示时区自 0.4.0 起按地点坐标查定（UI 设计规格 7.6），不再假设设备时区 = 地点时区；健康检查中「系统时区与地点时区不一致」一项即针对两者不一致时的提示。因此输入层设时间健康检查（触发条件与提醒文案见 2.2）：它不修正时间、只负责在时钟 / 时区可疑时把风险摆到用户面前。历算封装本身不读 GPS 时间、不做时钟校正。

### 4.2 验证方法（开发期执行，写进验收）

验证对象从「自研算法」变为「Engine 集成与封装的正确性」（时区、单位、J2000 / 当日坐标口径最容易错），方法不变：

- 暮光与日月出没：与 timeanddate.com 对同一地点同一日期逐项对照，容差 ±3 分钟（月出月落 ±5 分钟）；
- 月相照明比：与主流天文 App（如 Stellarium）同日对照，容差 ±3 个百分点；
- 目标高度曲线：抽 3 个目标 × 3 个时刻与 Stellarium 对照，容差 ±0.5°；
- 银心过中天时刻：与 PhotoPills / Stellarium 对照，容差 ±5 分钟；
- 食事件发现：与 NASA GSFC 日月食目录（2026–2035 子集）逐条对照，事件日期与类型必须全等；
- 抽查一组日出 / 月相时刻与备选库 commons-suncalc 交叉对照，差异超 2 分钟即立案排查（防封装层单位错误）。
- 全部验证做成本地单元测试的固定用例（金标准数值写死在测试里），升级 Engine 版本必须先过测试。

### 4.3 与曝光引擎的接口

历算只输出量，不做曝光决策：`天文夜起止、月亮照明比、月亮高度与天顶距、月亮-目标角距、目标赤纬、目标当前/峰值高度、银心窗口、流星雨辐射点高度曲线`。曝光引擎消费这些量（例如 NPF 用目标赤纬、月光贡献模型用照明比与几何量合成总天光，见第 5 节通则二）。接口以纯函数实现（Engine 本身无 Android 依赖，封装层同样保持纯函数），便于单测。

## 5. 计算层二：五类目标的曝光模型

通则：

- 每个模型输出统一结构：`推荐光圈、推荐快门、推荐 ISO、包围（快门与 ISO 两向各一档起）、理由（一句话，含所用关键量）、警告（可为空）、口径标注（所用公式与系数）`。
- 光圈不由公式「算」出，而是按目标类型从镜头常用光圈档中选（见 2.4）：星野类默认最大光圈或收 1 档（换锐度）；月亮默认 f/8–f/11（镜头甜点 + Looney 11 基准）；日食按曝光表查表。
- 快门取相机标准档位就近取整（1/3 档步进），Bulb 区间（>30s）给出整秒数并提示用快门线 / 间隔器。

#### 通则一：严苛程度三档体系（全局）

全 App 设一个全局「严苛程度」，三档：**严格 / 标准 / 宽松**，贯通所有模型（各模型不再各自设默认系数——swamp 系数 C 与 NPF 系数 k 均并入本体系）。各维度取值如下：

| 维度 | 严格 | 标准 | 宽松 |
|---|---|---|---|
| 拖线容忍（跟踪，5.2.2） | ≤1px，且用档案**最差漂移**算 | ≤1px，用**典型漂移**算 | ≤2px，用**典型漂移**算 |
| NPF 系数 k（5.2.1） | 1（100% 查图星点为点状） | 2（缩图 / 发布看不出） | 3（小幅面输出可接受） |
| 深空 swamp 系数 C（5.3） | 10 | 10 | 5（子曝光减半，靠总时长找补） |
| 单张背景目标位（流星雨封顶与广域 ISO 反推的直方图目标） | 约 20% | 约 25% | 约 33% |
| 月亮 / 日食 | 不适用（查表模型，无严苛维度；包围宽度按档位放宽一档备选） | 同左 | 同左 |

- **系统推荐档**：引擎按机身像素间距、焦距、跟踪状态给推荐并附一句理由。推荐规则（经验口径）：不跟踪且（焦距 ≥35mm 或像素间距 ≤5µm，如 A1 II）→ 推荐**严格**（拖线最先在此组合暴露）；跟踪且档案漂移为实测值 → 推荐**标准**（漂移已知，≤1px 典型值可信）；大像素机身（ZV-E1）或焦距 ≤24mm → 推荐**标准**并注明「大像素 / 短焦容忍度高，想更保险可升严格」；流星雨默认**标准**（背景目标位居中）。理由模板示例：「推荐严格：A1 II 像素间距 4.16µm、50mm 不跟踪，拖线容忍是当前瓶颈。」
- **用户可改**：每次计算可按次覆盖档位，也可在设置里改全局默认；覆盖只影响本次卡片，不回写系统推荐逻辑。
- **标注纪律**：参数卡片必须标注本次所用档位及来源（如「标准档（系统推荐）」/「严格档（手动）」），理由行引用关键量时与档位口径一致（见 7.1）。

#### 通则二：月光贡献与总天光模型（全局）

各模型不再直接使用「光害 Bortle」，而是使用**总天光**：

```
总天光亮度 = 光害基线（2.6 离线图谱 / 手动 Bortle 覆盖） + 月光贡献
合成在线性亮度域进行，再统一换算为 mpsas 与天光电子速率 R_sky 供各模型消费
```

- **月光贡献项**由四个历算量估算：月相照明比、月亮高度角（天顶距）、**目标与月亮的角距**、目标高度角。采用的简化模型：以 **Krisciunas & Schaefer (1991, PASP) 月光天光亮度模型**为骨架（月相函数 × 月亮天顶距消光 × 随角距变化的散射函数），辅以 **Winkler (2022) 单散射模型**的简化实现口径（开源调研结论，见 8.3 与附录 A）；不做完整辐射传输。误差声明：月光项为量级估算，受气溶胶与湿度影响可有 ±50% 量级偏差，与光害基线的误差声明叠加后，总天光的不确定性仍以 5.3 的口径为准（子曝光给区间 + 直方图复核）。
- **参与方式**：广域星空（5.2）的 ISO 反推与流星雨（5.5）的背景封顶改用总天光；深空（5.3）的 R_sky 改用总天光合成值；月亮本体（5.4.1）不使用总天光，继续用月相修正档位表（月亮是光源本体，不是背景）。
- **时间线联动**：当晚时间线（7.2）标注月出 / 月落，并给出**低月光干扰窗口**（月亮不在场，或月光贡献低于光害基线 1/3 的时段）——银河与深空的推荐窗口据此收紧。
- **降级提示口径（写死文案模板）**：当月光贡献使总天光亮度达到光害基线的约 4 倍以上（即天光变亮约 1.5 mag/arcsec²）且用户目标为深空或银河时，卡片顶部直言：「今晚月光强（照明比 X%、月亮在场至 HH:MM），深空 / 银河条件差：子曝光被天光压短、总时长等效打折明显。今晚更适合拍月亮本体或带月光地景的星野。」不粉饰、不只给参数了事。流星雨类的月光下调预期口径见 5.5。

### 5.1 带地景的星野

**它与其他类的区别（先讲清，再谈参数）**：构图里有**固定的地景主体**（山体、树线、建筑、湖面），成片是「地景 + 天空」的合成。因此本类的输出**不是一组参数，而是双套参数**，且两套的约束完全不同：

| 帧 | 约束来源 | 用什么模型 |
|---|---|---|
| 天空帧 | 星点拖线（不跟踪）或云台漂移（跟踪） | 按所选子情形直接复用 5.2.1（NPF）或 5.2.2（漂移模型），公式不重复定义 |
| 地景帧 | 环境光亮度与噪声（蓝调余光 / 月光 / 星光照明） | 本节地景帧口径；**不适用 NPF、漂移、swamp 任何星空模型——这条边界在卡片上明写** |

**地景帧的三条拍法（按用户所选给出对应参数段，可多选）**：

1. **蓝调时刻帧（首选）**：时机由历算给出——日落后民用暮光内（蓝调窗口的起止时刻上时间线）。参数口径（经验量级，标注「经验值」）：ISO 100–400、光圈 **f/5.6–f/8**（地景锐度与景深优先，与天空帧的大光圈口径相反）、快门随暮光加深在约 1–30s 量级滑动，给出「日落后约 10 / 20 / 30 分钟」三档起步量级并强提示以直方图为准。地景细节、色彩都优于纯夜拍，是本类的默认推荐拍法。
2. **夜间地景长曝帧**：无蓝调条件（到场已晚）时用。天光 / 月光照明下 ISO 400–1600、f/2.8–f/4、30s 至数分钟量级长曝（Bulb）；满月夜月光照明的地景亮度可接近黄昏量级，快门按月光贡献（通则二）粗修正并提示试拍。地景帧长曝不受拖线限制（地景不动），限制只来自热噪声与前景物（树梢风动、水面）移动。
3. **高 ISO 多张降噪帧**：ISO 3200–6400 连拍 8–16 张短曝，后期中值堆叠降噪。适用地景有微动（树叶、水面）不能长曝、或蓝调窗口已过的赶工场景；卡片给张数与单张参数口径，并提示堆叠只能压随机噪声、压不了前景物移动造成的重影。

**两段式拍摄流程（卡片附流程段，固定文案骨架）**：

1. 构图与机位一次锁定，之后两帧之间**不动机位、不改焦距**（合成对齐的前提）；
2. 先拍地景帧（蓝调窗口稍纵即逝，优先）——对焦于地景主体；或入夜到场时顺序反转，先天空后地景（夜间长曝版）；
3. 切天空帧前**重新对焦于星点**（两帧焦点不同，这是流程里最容易漏的一步，卡片单独列行提醒），开 / 关跟踪按天空子情形执行；
4. 天空帧里地景必然模糊（跟踪时）或星空帧与地景帧视角一致（不跟踪时），合成时地景一律以地景帧为准；
5. 两帧白平衡可不同（地景帧保留蓝调色温、天空帧按夜空），合成在后期完成（本 App 不做后期，见 1.2）。

**输出结构**：一张计划卡内含两段参数（天空段 + 地景段）与流程清单；严苛档位只作用于天空段（通则一），地景段只标注拍法与经验量级，不挂档位。

### 5.2 广域星空

广域星空指无固定地景主体的整片天空（银河、银河系内亮星云区、星座级大视场构图）。**银河是本类最重要的目标，但模型按「整片天空」组织，不再为银河单列一类**。本类含两个子模型，按所选跟踪档案自动二选一：不跟踪用 NPF 法则（5.2.1），跟踪用漂移模型（5.2.2）；两者的公式与口径与重构前一致。

#### 5.2.1 不跟踪（NPF 法则）

**完整公式**（Frédéric Michaud / Société Astronomique du Havre 提出的 NPF 法则，采用含赤纬修正的完整形式）：

```
t_max = k × (16.856 × N + 0.0997 × f + 13.713 × p) / (f × cos δ)

t_max：最长快门（s） N：光圈 f 值 f：焦距（mm）
p：像素间距（µm） δ：目标赤纬（°） k：容忍系数（见下）
```

- **简化式** `t = (35N + 30p)/f` 是完整式在 δ≈60° 附近的近似，PhotoPills 等广泛采用。两者在银心（δ = −29°）处相差接近一倍，**本 App 以完整式为唯一计算口径**，简化式仅在「口径标注」里供对照，避免用户拿外部计算器的简化结果对不上而困惑。
- **k（严苛系数）取值口径**：k 不再是本模型私有的选择，而是全局严苛档位的映射（见通则一）：**严格 k=1**（星点在 100% 像素查看下仍为点状，NPF 原义，对应约 ≤1px 级拖线容忍）、**标准 k=2**（缩图 / 网络发布看不出拖线）、**宽松 k=3**（小幅面输出）。本次所用 k 值随档位明示在卡片上；下文算例按 k=1（严格档）给出。
- δ 接近 ±90° 时 cos δ → 0 使 t 发散：实现上对 |δ| > 85° 封顶，并提示「近天极拖线不再是限制因素，改由天光 / 热噪声决定」。
- **500 法则对照**（只作对照展示，不参与推荐）：`t = 500 / (f × 裁切系数)`。差异说明写进卡片的「为什么」区：500 法则源于胶片时代，不含像素间距与光圈，对 50MP 的 A1 II 给出约 NPF 完整式 5 倍的时长（50mm 时 10s vs 约 2s），按它拍必拖线；对 ZV-E1 约 3 倍。引擎默认隐藏 500 值，用户可在设置里打开对照。

**计算示例**（50mm，银心 δ = −29°，k = 1；已按公式核算）：

| 相机 | f/1.4 | f/2.0 | f/2.8 | 500 法则（对照） |
|---|---|---|---|
| A1 II（p = 4.16µm） | 2.0 s | 2.2 s | 2.5 s | 10 s |
| ZV-E1（p = 8.40µm） | 3.3 s | 3.5 s | 3.8 s | 10 s |

读法：不跟踪时两台机器在 50mm 都被压到 2–4 秒量级，这正是需要 Polaris 跟踪的量化理由；ZV-E1 因大像素宽容约 1.7 倍。

**ISO 建议（不跟踪）**：快门被 NPF 锁死后，ISO 由「把直方图推到不过曝的 1/3–1/2 处」按**总天光**（光害基线 + 月光贡献，通则二）反推，引擎给档位区间：暗空且月光弱（图谱 Bortle 估计 ≤4）时 A1 II 约 ISO 3200–6400、ZV-E1 约 ISO 3200–12800（大像素 + 低读噪允许更高）；总天光每变亮约 1 等，区间整体下移约 1 档 ISO。并提示若已达区间上限仍欠曝，应改走跟踪模式而不是继续升 ISO。此区间为经验口径，会在卡片上标注「经验值」。

**设计注记（实现口径）**：上述 ISO 锚点原本只针对两台内置机身给出。向自定义机身推广时，采用像素间距 6.3µm 分界的启发式：像素间距 ≤6.3µm 的机身就近采用 A1 II 锚点，>6.3µm 的机身就近采用 ZV-E1 锚点。两锚点像素间距为 4.16µm 与 8.40µm，中点 6.28µm，取约值 6.3µm 作分界——该分界是按像素间距就近锚定的实现口径，不改变两台内置机身的设计值。

#### 5.2.2 跟踪（漂移模型）

**核心换算**（与基线实测报告同一口径，这是两条线对齐的关键）：

```
像元角尺度 s (″/px) = 206.265 × p (µm) / f (mm)
容许单张时长 t_max (s) = 容忍位移 (px) × s / 漂移率 D (″/min) × 60
```

- 容忍位移与漂移取值由全局严苛档位决定（见通则一）：**严格 = ≤1px 且 D 取档案最差漂移；标准 = ≤1px 且 D 取典型漂移；宽松 = ≤2px 且 D 取典型漂移**。（与实测报告的判定标准一致：实测报告给出「≤1px / ≤2px 对应的最长曝光」，本 App 用同一公式由档案漂移率反推，两个来源应互相吻合，验收时交叉核对。）
- 漂移率 D 来自所选跟踪档案（见 2.5）；档案未实测时**留空处理**：跟踪卡片**不给具体秒数**，只给出本节的换算关系与公式说明，并明确标注「待基线实测录入」；实测录入典型 / 最差双值后，卡片恢复秒数输出、标注消失。绝不用估计值占位计算——占位数字一旦被当真，会给出误导性的最长曝光。

**示例**（50mm；D 为示例假设值 10 ″/min，非实测，仅演示换算）：

| 相机 | s (″/px) | ≤1px | ≤2px |
|---|---|---|---|
| A1 II | 17.1 | 103 s | 206 s |
| ZV-E1 | 34.7 | 208 s | 416 s |

（D = 5 ″/min 时各时长翻倍，D = 20 ″/min 时减半，实现时按档案现算。）

**ISO 随之下降的逻辑**：跟踪解除快门上限后，曝光三要素的优先级反转——先定光圈（最大或收 1 档），快门取 t_max 内一个整洁值（如 60s / 120s），ISO 从不跟踪时的高位**往下调**到使直方图落位的档：典型落点 A1 II 在 Polaris 单星档案、60s 时约 ISO 800–1600（与此前速查表的跟踪行一致）。引擎规则：ISO 优先吸附到双增益切换点附近（A1 II 机械快门 640、其上下各一档为首选候选），理由文案写明「已到第二增益点，读噪最低区间，继续降 ISO 只会欠曝」。

**地景合成提示**（不计算、只提示）：跟踪拍银河时地景必糊，卡片附一行固定提示：「地景请另拍一张未跟踪帧（可用本 App 不跟踪模式参数），后期合成。」与用户既定的两段式拍法对齐。

### 5.3 深空目标（子曝光模型）

**子曝光公式（swamp 标准）**：

```
目标：单帧背景天光电子数 S_sky = C × RN² （RN：所选 ISO 处读出噪声，e⁻）
子曝光时长 t_sub = C × RN² / R_sky
R_sky：天光电子速率（e⁻/px/s），由天光亮度、光圈、像素面积、QE 估算（见下）
C：swamp 系数 — 5 或 10 两档
```

- **C 的取舍**：C = 10 时读噪对总噪声的额外贡献约 5%（叠加效率约 95%），是 Robin Glover（SharpCap）论证的「足够好」标准；C = 5 时额外贡献约 10%，子曝光时长减半，代价是需要更多总时长找补。C 由全局严苛档位决定（见通则一）：**严格 / 标准 C = 10、宽松 C = 5**；卡片主值按当前档位给出，另一档的秒数作对照行并列（便于用户临场改主意），不再让用户裸选系数。坚决不用 C = 20 以上：收益 <2% 而时长翻倍，且亮星饱和与废帧损失陡增，文案中说明这一判断。
- **上限护栏**：t_sub 同时受跟踪档案 t_max（5.2.2）封顶——深空子曝光取 `min(swamp 时长, 跟踪容许时长)`；并受单帧经验上限（默认 600s）封顶，触顶时提示「已达上限，按上限拍、靠总时长补」。

**R_sky 的估算方法与误差声明**：

- 输入通道：**总天光**（2.6 的光害基线——离线图谱 mpsas，或手动 Bortle 覆盖换算的 mpsas——加通则二的月光贡献，合成后的 mpsas）→ 按 Glover 的方法学框架（tools.sharpcap.co.uk 的公开计算思路）结合光圈 f、像素间距 p（面积 ∝ p²）、相机 QE 参考值，估算宽带（无滤镜）R_sky；窄带滤镜按带宽比例下调（字段预留，MVP 不做窄带，见第 9 节）。
- **误差声明（写进卡片理由区，固定文案）**：「天光速率由图谱与月光模型估算，误差可达 ±50% 甚至 2 倍；子曝光秒数只取数量级意义，请用试拍直方图复核（背景峰落在 20%–30% 处即达标）。」图谱建模值的时效偏差、月光简化模型的量级误差、目标高度的大气消光都在此误差内，不再逐项建模。这是本 App 全部模型中不确定性最大的一处，产品上靠「给区间 + 给复核方法」而不是假装精确来处理。

**示例**（演示量级，R_sky 为假设值）：RN 取 HCG 段 1.1 e⁻ 时，C·RN² = 12.1（C=10）/ 6.1（C=5）e⁻。若 f/2、宽带、Bortle 5 级天光下 R_sky 假设为 0.5 e⁻/px/s（ZV-E1 量级），则 t_sub ≈ 24s（C=10）；同一条件下 A1 II 因像元面积小 4 倍，R_sky 约 0.125 → t_sub ≈ 97s。再对照低 ISO 未切换段 RN = 3.5 e⁻ 的情形：C·RN² 涨到 122.5 e⁻，t_sub 直接放大 10 倍——这张对比就是「深空必须把 ISO 顶到双增益切换点」的定量理由，引擎会把用户当前所选 ISO 若落在切换点以下时的此项惩罚算出来并提示。

**总累积时长与张数**：

- 总时长按目标类型给经验分档（宽带、暗空基准）：明亮星团 / 星云（如 M45、M42 量级）1–2 h；一般星系 / 暗星云 3–5 h；极暗目标 6 h 以上并提示分多晚累积。总天光显著高于光害基线时（月光强或图谱 Bortle 估计高）按「有效时长打折」提示（只给折扣系数文案，不伪造精确换算）；月光达到通则二的降级阈值时，本类卡片先出「今晚不适合深空」的直言提示再给参数。这些分档是经验口径，卡片标注「经验值」。
- 张数 = 总时长 / t_sub（向上取整），同时给出总数据量估算（张数 × 单帧 MB，A1 II 的 50MP RAW 约 55–65MB / 帧量级，ZV-E1 约 13–15MB 量级），提醒存储与电量——低功耗、移动供电场景下电量同样是硬约束，计划页给出「按此计划约需 X GB、约 Y 百帧」的预算行。

**ISO / 增益选择规则（深空）**：

1. 首选 = 双增益切换点（A1 II：机械 640 / 电子 500；ZV-E1 照片口径待核实前，用其 ISO 不变区间的保守值并标注）；
2. 天光极强（高 Bortle / 月光强）时可降一档换动态范围，引擎给出权衡文案；
3. 切换点以上继续升 ISO 不再降读噪（ISO 不变性），引擎明确阻止「无意义的高 ISO 推荐」，只在被跟踪时长逼到极短时才放行并说明理由。

### 5.4 月 / 日食

月与日食同属「日月本体与事件」一类，下含两个子模型：月亮本体（几乎每晚可用）与日食（事件型，带安全闸门）。两者的公式与口径互不借用，月亮的月相修正表不适用于日食、日食的曝光表也不反推月亮。

#### 5.4.1 月亮

**公式（基准）— Looney 11 法则**：满月、晴朗、高空时，f/11 下快门 = 1/ISO（秒），即 ISO 100 → 1/100s @f/11。月亮是被阳光直射的天体，按「白天曝光」处理，这也是自动测光容易翻车、必须给固定基准的原因。

**等效换算（用户实际光圈不是 f/11 时）**：保持曝光值不变换算，例：ISO 100、满月、改用 f/2.8 → 快门 1/1600s（f/11→f/2.8 共开 4 档，1/100 → 1/1600）。引擎内部按 EV 换算并落到最近标准档。

**按月相照明比的修正档位表**（对基准曝光的增量，正值 = 加曝光；照明比由历算给出）：

| 月相 | 照明比 | 修正 | 备注 |
|---|---|---|---|
| 满月 | ≥ 97% | 0 档 | Looney 11 直接适用；满月无影、环形山对比最低，文案提示「细节平淡属正常」 |
| 盈凸 / 亏凸 | 75%–97% | +1 档 | |
| 盈凸 / 亏凸（近弦） | 60%–75% | +1.5 档 | 半档以相机 1/3 档步进执行 |
| 上弦 / 下弦 | 40%–60% | +2 档 | 晨昏线阴影最丰富，文案主推 |
| 娥眉月 | 15%–40% | +3 档 | |
| 细眉 / 残月 | < 15% | +4 档 | 另给「地照（地球反照）」独立起步值：以亮面曝光为基准再 +5 至 +6 档量级长曝（秒级），并提示亮面必然过曝、需两张合成——地照为独立小模式，不并入主卡片数值 |

边界规则：照明比恰在区间边界上时，归入照明比较高的一档（如 40% 按 40%–60% 档、75% 按 75%–97% 档、15% 按 15%–40% 档）。

月相名称（新月 / 娥眉月 / 上弦 / 盈凸月 / 满月 / 亏凸月 / 下弦 / 残月）的分档口径主存于 UI 设计规格（docs/ui-design.md §7.4）：按月相角 θ（日月黄经差）八分，每档 45°、互斥无缺口；本节的修正表按照明比分档，与名称分档是两套独立口径，不互相套用。

说明：各家资料对弦月修正有 +1 至 +2 档的分歧（取决于按「亮面正确曝光」还是「整体观感」），本表取偏保守（曝光略多）的一侧，并用 ±1 档包围吸收分歧，按保守侧执行。

**高度角修正**：月亮高度 <15° 时大气消光明显，建议额外 +1 档并提示色偏与抖动（seeing）；高度由历算给出。

**输出例**（A1 II，50mm 实际多为构图用途，此处以数值结构示意）：满月、ISO 100、f/11 → 1/100s，包围 1/80–1/125；若用 f/2.8 则 1/1600s。理由文案：「满月按 Looney 11，照明比 99%，无月相修正。」

#### 5.4.2 日食（日全食 / 日环食）

**定位声明（界面与本文件一致）**：本模块是**曝光参数参考表**，不是日食观测安全指南。安全规范（滤镜标准 ISO 12312-2、摘镜时机等）以 NASA / 美国天文学会（AAS）指南为准，App 在模块入口与每次计算前都展示安全闸门（见下）。

**曝光表结构**：以 Jerry Lodriguss（AstroPix）日食曝光表为蓝本结构（开发期录入时再与其原表逐格核对并标注出处），组织为「现象 × 光圈 → 快门」的矩阵，基准 ISO 100、无滤镜（全食期）/ ND5.0 减光（偏食期），换 ISO 按 EV 平移。下表为 ISO 100 的结构示例（节选列）：

设计要点：

1. **全食期是一组包围序列，不是单值**：日冕亮度跨度达 10 档以上，卡片直接给出「从 1/2000 到 8s 的包围序列」作为拍摄计划，并按内置静态食表给出的中心线全食时长（构建期管线自 NASA 目录生成，见 6.1 / 8.4）提示每轮序列可重复次数。
2. **贝利珠 / 钻石环只给提示性说明**：持续数秒、强依赖月缘地形，不承诺可计划性，给「现象说明 + 参考单值 + 连拍建议」，卡片上明确标注「提示性，不保证」。
3. **偏食期与全食期在数据上完全隔离**：偏食期行强制带滤镜标记；环食（日环食）全程无「摘镜窗口」，模块按食分类型分支：若为环食，整个表锁定为滤镜模式（此为安全关键逻辑，写进单测）。
4. **本地接触时刻缺口（明确的功能边界，非缺陷）**：历算引擎（Astronomy Engine）只给**事件级**预报——哪天发生、什么类型、全球最大食分；**给不出用户所在地的初亏（C1）/ 食甚 / 复圆（C4）时刻与本地食分**。该量需按 NASA 日月食目录的**贝塞尔元素**另行自算（月影锥几何 + 观测点坐标 + ΔT 地球自转改正，ΔT 的不确定性本身带来秒至分钟级误差）。排期：**v1.1 自研**（见 9.2）；**v1.0 的日食功能边界明确为「事件提醒（第 6 节目录）+ 分阶段曝光参考表」，不承诺本地接触时刻**；全食时长、食分、食带等目录级字段由构建期管线自 NASA 目录生成静态食表内置（见 6.1 / 8.4），**不手输**。此缺口已登记第 10 节风险；界面文案不得出现暗示本地时刻已算出的表述，因为摘镜时机与本地时刻直接相关（安全口径）。

**安全闸门设计（不可绕过）**：

- 进入日食模块先出安全页：要点（偏食期全程滤镜、摘镜仅限全食期完全食既阶段、取景器直视风险）+ 一个**不可关闭的确认步骤**（需主动勾选「我了解偏食阶段必须使用合格日食滤镜」才进入计算；每次进入都确认，不提供「不再提示」）。
- 计算结果页顶部固定红条：当前所选阶段的滤镜要求（偏食期 = 「滤镜：必须」；全食期 = 「滤镜：已摘除窗口，仅限全食期 X 分 X 秒」）。
- App 不提供任何「倒计时自动摘镜」类功能。食带信息以**目录级数据**呈现（中心线路径概述、食带宽度、中心线全食时长，来自构建期管线生成的静态食表，见 6.1），但**不做**基于定位的「你在不在全食带内」自动判定——目录级粗粒度数据不足以支撑安全相关判定；食分类型（全食 / 偏食模式）由用户按所选事件自选。本地接触时刻的自算排 v1.1，见设计要点 4。

### 5.5 流星雨

**拍法本质（与前四类都不同，先讲原理）**：流星是划过天空的**瞬时光迹**（持续零点几秒到数秒），其在单帧上的亮度由流星本身的光度决定，**与快门时长无关**——拉长单张不会让流星更亮，只会持续抬高天光背景、降低光迹与背景的对比。因此本类的曝光逻辑是反的：不是「尽量多收集光」，而是**连续无间隔连拍数小时，用足够多的帧数覆盖随机出现的流星；单张曝光的上限由「天光背景不过曝」封顶**。本类默认不跟踪（固定三脚架对准取景空域；开跟踪会让辐射点钉在画面同一点、构图与地景关系反而受限，需要时用户自选跟踪档案，模型公式不变）。

**单张参数推导口径（三步，写死）**：

1. **定光圈**：最大光圈或收半档（流星集光靠光圈与 ISO，不靠时长）；
2. **定单张时长上限**：取两者的较小值——①NPF 最长快门（5.2.1，防星点拖线，仅作**上限参考**）；②**天光封顶时长**：以**总天光**（光害基线 + 月光贡献，通则二）估算背景累积速率，使单张背景落在严苛档位给定的直方图目标位（严格约 20% / 标准约 25% / 宽松约 33%，见通则一）。暗空无月夜通常是 NPF 先到顶；光害重或有月光时天光先封顶，卡片须明示今晚是哪一项在限制（「限制因素：天光」/「限制因素：拖线」）；
3. **定 ISO**：在选定单张时长下把背景推到目标位所需的 ISO，优先吸附双增益切换点附近（与 5.2.2 同一吸附纪律）；ISO 取向是严 / 宽档在本类的主要落点之二（另一落点即背景目标位）——严格档宁可 ISO 略低保对比，宽松档允许背景位更高换单张更短、帧数更多。

**内置流星雨表（静态数据，随 App 版本更新）**：主要年度流星雨约 20–30 场（象限仪座、宝瓶座 η、英仙座、猎户座、狮子座、双子座等），字段：`IAU 三字母代码与编号、中文名、活跃期（起止太阳黄经）、峰值（太阳黄经，运行时由 Engine 反推当年公历日期）、峰值 ZHR 量级、辐射点 RA/Dec 及逐日漂移、母体天体、地心速度、数量指数`。数据口径：按 **IMO（国际流星组织）Shower Calendar / Working List** 与 IAU Meteor Data Center 的公开年表整理（见 8.3 与附录 A）；定位为**历算年表级**——逐年峰值的精确时刻有年际浮动，界面允许用户手调峰值日期 ±1 天，ZHR 一律标注「量级预期，非承诺」。

**辐射点与时间线**：所选流星雨的辐射点用 `DefineStar` 建为目标（RA/Dec 按日期漂移插值），高度曲线并入当晚时间线（7.2）；卡片给出「辐射点升至 30° 时刻」「峰值夜辐射点最高时段」作为开拍建议。峰值不在今晚时，卡片直言与峰值的天数差与 ZHR 衰减预期，不假装今晚就是好夜。

**取景建议（经验口径，标注「经验值」）**：镜头中心**偏离辐射点约 30–45°** 取景——正对辐射点流星光迹短而密，偏开后光迹更长、更出片；同时兼顾银河 / 地景构图（与 5.1 的地景帧可同夜串联：地景帧共用，流星连拍帧兼作天空素材）。辐射点高度太低（<20°）的时段建议等升高后再开连拍。

**月光干扰（本类对月光最敏感，单独口径）**：与通则二共用月光贡献模型，但评估结论单独呈现：按照明比与月亮在场时段给出**预期下调**提示（如「照明比 78%、月亮在场至 02:10：可见流星数预期较无月峰值大幅下调，暗流星基本被背景淹没；建议主攻月落后时段」）；满月撞峰值时直言「今晚以体验与试拍为主，不值得为存储与电量通宵连拍」。这是五类中唯一把月光结论放在参数之上的类别。

**连续拍摄的电量 / 存储估算（计划段，固定输出）**：按「连拍总时长（用户填，默认给峰值夜建议值）÷（单张时长 + 间隔，间隔按 ≈0 设计、仅留机身处理间隙约 1s 估算）= 总张数」，乘单帧文件大小（按相机记录：A1 II 约 55–65MB、ZV-E1 约 13–15MB 量级）给出总数据量；电量侧给「约 X 百帧 / Y GB」预算行并提示长夜连拍的供电安排（低功耗、移动供电场景下，相机供电自理部分只提示不计算）。

**输出结构**：单张参数三件套 + 限制因素标注 + 辐射点关键时刻 + 取景偏离建议 + 月光预期段 + 连拍预算段。与严 / 宽三档的衔接已写在推导口径第 2、3 步（背景目标位与 ISO 取向），卡片标注本次档位（通则一纪律）。

## 6. 计算层三：当日最佳目标库（按日期 + 地点跨类别推荐）

本模块回答的问题与第 5 节不同：第 5 节是「目标已定，怎么拍」；本节是「今晚、此地，**拍什么最值得**」——按当日日期 + GPS 地点，跨类别（深空、广域星空、日 / 月食、流星雨、星座）给出当晚的推荐榜单。它消费第 4 节历算、通则二月光模型与第 2 节的设备 / 环境输入，不新增用户输入（地点与日期沿用全局选择）。

**「本地是否可见」的判定方法（写清口径，不装精确）**：

- **日食**：只作**粗判**——用目录的可见区域概述与本地经纬度做包含判定，给「可见（偏食）/ 可能在全食带附近 / 不可见」三档结论并**标注不确定性**（全食带宽度仅百 km 量级，粗判不能替代食带地图）；本地接触时刻 v1.0 不提供（见 5.4.2），目录条目点开后引导到 5.4.2 的曝光参考与安全闸门。

### 6.2 推荐引擎（评分模型）

对给定夜晚，逐个候选目标（深空库 + 广域看点 + 星座条目 + 当晚事件）打分，全部因子归一到 0–1：

| 因子 | 口径 |
|---|---|
| 高度窗口分 | 天文夜窗口内：峰值高度（越高越好，<20° 重罚）与高度 >30° 的持续时长（越长越好）的合成 |
| 月光分 | 由通则二月光模型给：目标处月光贡献越低越高；满月夜深空类整体趋零 |
| 视场匹配分 | 目标角尺寸 vs 用户**镜头库各镜头**的 FOV：目标占画面短边约 1/10–1/2 为佳（广域看点按大视场口径另算），同时产出「推荐镜头」（得分最高的镜头） |
| 光害适配分 | 目标表面亮度 vs 本地总天光基线：表面亮度低于天光可分辨门槛的目标在高 Bortle 地点**降权直至过滤**（暗目标不硬推）；明亮目标在城市点位相对升权 |
| 可拍时长分 | 目标处于推荐窗口（高度、月光、低遮挡——预留与地平线档案的接口，MVP 不启用）内的有效时长占天文夜的比例 |

- **聚合方式**：加权**几何平均**（借鉴 DarkHours 的聚合思想，见 8.3）——`总分 = Π 因子分 ^ 权重`，任一因子趋零则总分趋零，防止「月光满分掩盖光害短板」式的算术平均假象。权重为**经验权重**并可在设置中三档调整（均衡 / 画质优先 / 出片率优先）：均衡档示例权重——高度 0.30、月光 0.25、视场 0.20、光害 0.15、时长 0.10（和为 1，开发期以固定夜晚用例校准后写死，见 8.6）。
- **类别配额**：榜单按类别设上限（默认 Top 10 内深空 ≤5、广域 ≤3、星座 ≤2），避免清一色星系；配额在聚合后做重排，不改单目标分数本身。
- **事件置顶逻辑**：日 / 月食（当晚发生且本地可见 / 粗判可见）与流星雨（距峰值 ≤1 天且 ZHR 量级达标）**不参与普通评分排序**，按「事件临近度 × 本地可见性」单独置顶于榜单头部并标「事件」角标——事件的可遇不可求优先于常驻目标的分数高低。
- **诚实降级**：无月夜 / 满月 / 光害极重导致全榜低分时，榜单照出但顶部给出总评文案（如「今晚条件总体偏差：月光强 + 光害高，榜单以月亮与亮目标为主」），不拿低分目标充数拔高。

### 6.3 输出

- **「今晚最佳」榜单**（第 7 节输出层的一种呈现）：排名 + 类别角标 + 每条**一句理由**（由最高与最低因子模板生成，如「过中天高度 68°、无月光窗口 3.5 小时；表面亮度高，Bortle 5 的郊区地点亦可」）+ **推荐镜头** + **最佳时间窗**（起止时刻）。
- **与时间线打通**：点榜单条目 → 当晚时间线（7.2）叠加显示该目标的高度曲线与推荐窗口；点「去计算」→ 带入第 5 节对应类别模型（输入预填，见 2.7）。
- 榜单按全局日期 / 地点实时重算（纯本地计算，数百条 × 采样点，性能无议题），不缓存跨夜结果。

### 6.4 分期结论（与第 9 节同步）

- **v1.0 只做简化版「今晚概览」**：事件（食目录 + 流星雨峰值临近）、银心窗口、当晚月相小结，外加从深空库中按「明亮 + 当晚高度好」静态规则挑出的 **Top 约 10 条明亮深空**（不跑完整评分，只用高度与星等两因子）。理由：完整评分引擎的权重校准需要真实夜晚的对照样本，赶工上线只会给出貌似精确的伪排名；而概览版的数据层（目录与库）与 v1.1 共用，先行不浪费。
- **0.9.0 中间形态**：概览的深空短名单扩展为跨类别榜单——星座（88 小表）与广域银河看点（首批 7 条）按分类门槛与配额入榜（深空 ≤5、广域 ≤3、星座 ≤2，不跑评分、不跨类转借），流星雨辐射点以泳道呈现；呈现走时间轴弹窗与类目筛选，规格见 UI 设计规格 §7.8。此形态只扩数据层与组榜门槛，评分仍留 v1.1。
- **0.10.0 形态**：时间轴保留配额精选（榜单不变），卡头弹窗由榜单改达标全量——组榜装配输出每类门槛通过者全量（达标集）与辐射点达标集，弹窗按类分区呈现全部达标者并以金色「推荐」标记回指榜成员；区内序沿用现行类内序（深空星等、星座 / 广域中天高度、辐射点峰值接近度），五因子评分仍留 v1.1，届时只替换达标集的区内排序函数。
- **v1.1 做完整版**：全库接入 + 五因子评分 + 类别配额 + 权重三档 + 与时间线联动。
- **工作量增量估计（估计值）**：数据层整理与校验约 2–3 天（一次性，含 OpenNGC 裁剪脚本与食目录录入）；v1.0 概览版约 +2–3 天；v1.1 评分引擎与联动约 +1 周。均已计入第 9 节各期估计。

## 7. 输出层设计

### 7.1 参数卡片（核心界面，一屏一张卡）

固定版式，自上而下：

1. **标题行**：目标类型 + 关键输入摘要（如「广域星空 · 跟踪 / 50mm / A1 II / Polaris 单星档案」）。地景类（5.1）为双段卡：天空段与地景段上下分区，各带自己的标题行。
2. **主参数三件套**（大字）：光圈、快门、ISO。
3. **包围行**：快门 −1 档 / +1 档两个备选（Bulb 段给秒数）；ISO 备选一档；标注各自代价（如「+1 档：星点拖线风险↑」）。
4. **理由行**（一句话，模板生成，含关键量）：例「漂移率 10″/min（典型）、像元尺度 17.1″/px，≤1px 容忍 → 上限 103s，取 60s 整档；ISO 吸附至双增益点 640 上方一档。」
5. **档位与警告行**：**固定标注本次严苛档位及来源**（如「标准档（系统推荐）」，见通则一）；条件角标（出现才显示）：「基于未实测漂移」「读噪待核实区间值」「天光为图谱估算」「月光强，条件降级」等，见各节定义。
6. **固定页脚**：「起步值 — 请以直方图与试拍为准，亮部不溢出优先。」

卡片支持一键存入「今晚计划」（连同输入快照），也支持复制为纯文本分享 / 粘贴到笔记。

结果完整性口径（0.7.1 补）：任一输入校验失败时，先前结果卡必须同步清除，不得出现「标注与输入已经一致、数值仍是旧结果」的半更新状态；计算入口在无可计算组合时禁用。此二条与 UI 设计规格 §4 的计算器输入条款互为落点。

### 7.2 当晚时间线视图

一条横向时间轴（日落到次日日出），叠放四层信息：

- 暮光带：日落 → 民用 / 航海 / 天文暮光结束，天文夜区间高亮，天文暮光开始 → 日出；
- 月亮：月出 / 月落标记、照明比标注、月亮在场区间以浅色带表示；并按通则二标出**低月光干扰窗口**（月亮不在场或月光贡献低于光害基线 1/3 的时段）；
- 目标：所选目标（银心、深空目标、或流星雨辐射点）的高度角曲线（简化为色带 + 关键点标注：升至 30°、过中天时刻与峰值高度、落至 30°）；从第 6 节榜单点入时自动叠加该目标曲线；
- 推荐窗口：各层交集出的「黄金窗口」用醒目色块标出，并直接标注起止时刻（如「23:10–02:40，银心 >30° 且低月光」）。

本节全形态已随 0.4.0–0.6.0 分期落地（静态四层 → 游标 → 弧段分段 → 推荐区间与月光剔除），即现行实现；早期的「关键时刻列表」形态为其前身。图形时间轴原排 v1.1，提前交付的变更登记见第 11 节补充行。

### 7.3 拍摄计划的保存与导出

- 保存内容：日期、地点、相机、镜头、跟踪档案、环境、目标、输出卡片全文、生成时间、所用数据版本（如读噪表版本、漂移档案来源日期）。
- 存储：本地（见 8.4），列表按日期倒序，可删。
- 导出：纯文本（.txt）单文件，格式为人类可读的分节文本（含全部参数与理由），通过系统分享面板发出；不做 PDF / 图片导出（MVP）。
- **数据迁移（进 v1.0）**：计划与设备库（相机 / 镜头 / 跟踪档案 / 收藏地点）支持一键导出 / 导入 JSON，作为换机与备份兜底；与上面的纯文本计划导出是两回事（前者给人看，后者给机器回灌），入口分开、互不替代。

### 7.4 红光模式（v1.0 必做）

- **全局红光主题**：深红配色 + 压低整体亮度，保护暗适应；**全部界面**适配，不留白名单——参数卡片、当晚时间线、今晚最佳、输入页、设置页一律红光呈现（图表曲线、角标、警告条改用红色系内的明暗与线型区分，不依赖红以外的颜色传达信息）。
- **开关**：一键开关（主界面常驻入口）+ 可选「日落后自动开启」（按历算日落时刻触发，用户可在设置中关掉自动项）。
- 红光模式只改呈现、不改任何计算与数据；验收时逐屏走查无漏网界面（与日食安全文案的逐屏检查同列，见第 10 节）。

## 8. 技术方案

### 8.1 平台与语言

- Android 原生，Kotlin，单模块起步、按功能分包；**首要测试设备：OPPO（ColorOS 17）**：最低 API 以该机实际 Android 版本为准放宽，开发启动时以真机核对后写死（本文件不臆断版本号）；测试机型即该机，不另设机型矩阵。ColorOS 的权限与后台管理较严：本 App 为**前台使用型**（无后台常驻、无定时唤醒需求，天然避开后台限制重灾区），但 GPS 权限申请流程须按 ColorOS 的实际弹窗与权限分组在真机上验证一遍（列为开发期验证项）。
- 核心依赖只有一个：**Astronomy Engine（Kotlin 版，MIT）**，以单文件源码形式纳入工程并记录上游版本（不走 JitPack 运行时拉取，避开其构建不稳定性；升级时整文件替换并先过 4.2 的金标准用例）。其余计算（曝光引擎、月光模型、评分）全自研，无第三方运行时依赖。
- UI：Jetpack Compose（单人维护、界面简单，Compose 的迭代速度占优）；全局深色「夜视友好」界面：暗底、低亮度；**红光模式为 v1.0 必做**（全局红光主题、一键开关 + 可选日落后自动开启，规格见 7.4）。
- **界面语言**：中英双语——**汉语默认、英语可切换**，切换即时生效、不重启；字符串资源双语维护。天文术语在两种语言下都保留英文原词、并附当前语言注释（如「NPF（No-Parallax... 法则）」式的原词 + 注），避免翻译腔把术语译丢。
- 无任何网络权限声明：`AndroidManifest` 不申请 INTERNET 权限——这是「全离线」承诺的可验证证据，用户装机时可查。

### 8.2 模块划分

```
app
├─ ephemeris/ 历算封装：Astronomy Engine 薄封装（日月位置、暮光、月相、食搜索、目标曲线、银心/辐射点窗口、星座判定）+ 窗口交集判定（纯函数，无 Android 依赖）
├─ engine/ 曝光引擎：五类目标模型 + 月光贡献模型 + 严苛档位推荐 + EV 换算与档位吸附（纯函数，输入输出皆数据类）
├─ catalog/ 静态目录：深空库（OpenNGC 裁剪）、恒星子集（HYG）、星座表、流星雨表、日月食目录、广域看点、光害网格（构建期产物，只读）
├─ recommend/ 当日最佳：候选打分（几何平均聚合）、类别配额、事件置顶、今晚概览（第 6 节）
├─ data/ 设备库：相机表（含读噪子表）、镜头表、跟踪档案、收藏地点、计划记录（Room）
├─ ui/ Compose 界面：输入页、卡片页、时间线、今晚最佳、计划列表、设置（含数据来源页）
└─ export/ 纯文本计划导出 + JSON 数据导出 / 导入
```

边界纪律：`ephemeris/`、`engine/`、`recommend/` 不得引用 Android API，保证全部计算可在 JVM 单元测试里跑（见 8.6）。

### 8.4 数据存储

- 选 **Room（SQLite）**：相机 / 镜头 / 档案 / 地点 / 计划都是结构化小数据，Room 的迁移机制对后续加字段（读噪逐点表、窄带滤镜表）友好；总量在 KB–MB 级，无性能议题。
- 内置数据（两台相机、静态目录）以种子数据形式随 APK 发布，带 `dataVersion` 字段；用户自定义条目与内置条目分表存放，升级 App 时内置表可整表替换而不伤用户数据。
- **构建期数据管线**（不进运行时，产物进 `catalog/`）：OpenNGC 裁剪转换（含 PosAng 回补）、HYG 亮星子集（`build_stars.py`：二进制星表加名表，源文件 SHA-256 校验与参宿四坐标断言钉死赤经十进时换算）、d3-celestial 连线转换（`build_lines.py`：顶点按 HYG 星 id 对齐并断言容差）、流星雨表的录入校验、Falchi 图谱重采样（降采样 + 量化 + 陆地掩膜，体积预算见 2.6）；每条管线产出带来源与日期的元信息，随「数据来源」页展示。
- **NASA 食目录管线**：一次性开发侧脚本抓取 eclipse.gsfc.nasa.gov 的 2026–2035 日 / 月食目录页并解析为静态食表（含食带、食分、中心线全食时长等目录级字段，见 6.1）。GitHub 核查结论：**未发现可信、活跃维护的现成 NASA 食数据抓取 / 整理项目可直接复用**——命中的只有学生级数据分析 / 可视化作业仓，不构成管线参考；而 NASA 目录页本身是规整的定宽 HTML 表格、贝塞尔元素官方另以 CSV 发布，故用一个小型专用解析脚本即可，**无需重型爬虫框架**。脚本只在构建期由开发侧运行，App 本体无任何抓取行为（与 8.1「不申请 INTERNET 权限」纪律一致）。
- 读噪逐点表、光害网格、目录更新都通过发新版 APK 完成（无联网更新通道，符合离线定位）。

### 8.5 签名与分发

- **独立 keystore**：本 App 生成一把全新的专用签名密钥，不与任何其他项目共用；理由：签名密钥的风险与生命周期应彼此独立——其他项目的密钥遗失 / 轮换不影响本 App 的覆盖升级，反之亦然。
- 分发：APK 侧载（本地文件传输安装），版本号语义化（见第 9 节路线）；每次发版附 SHA-256 校验值与变更说明。
- **定名**：中文名「**曝光参谋**」，英文名 **AstroExposure**，包名 `app.astroexposure`。理由：名称对应功能（给参数、出主意），英文名与仓库名一致、便于双语界面与数据文件命名。图标方向：深色底 + 光圈叶片 / 星点 motif，具体图稿于开发期制作。包名独立，可与云台控制类 App 同机共存。

### 8.6 关键算法验证策略

| 对象 | 验证方法 | 容差 / 通过标准 |
|---|---|---|
| 历算封装（暮光、月出月落、照明比、过中天、食事件） | 与 timeanddate、Stellarium、NASA 食目录的金标准用例对照（固定地点 × 固定日期的一组数值写死进单测）；另与 commons-suncalc 抽查交叉 | 见 4.2 各容差 |
| 月光贡献模型 | 与 Krisciunas & Schaefer 原文算例及公开月光计算工具同参数对照总天光量级 | 数量级一致（±50% 内，与通则二误差声明匹配） |

### 9.4 v1.2+ 远期展望（仅登记、不排期、不进 v1.0 / v1.1 范围）

## 10. 风险与限制

1. **推荐值的性质**：全部输出是基于经验公式与估算数据的**起步点**，不是测光仪读数。最大不确定性排序：总天光估算（光害图谱建模值的时效偏差 + 月光简化模型误差，合计 ±50%–2 倍）> 漂移实测值本身的工况波动（档案典型 / 最差区间；未实测期间跟踪秒数留空、不输出，无占位值风险） > 月相修正档位的文献分歧（±1 档）> 历算（Engine ±1′ 级，可忽略）。产品对策已经内嵌在设计中：给区间、给包围、给现场复核方法（直方图位置、试拍查星点），而不是追求单点精确。
2. **日食安全责任边界**：App 提供参数表与强制确认闸门，但**不能也不声称能保证观测安全**；滤镜真伪、摘镜时机、眼病风险等以 NASA / AAS 指南与用户自备的合格器材为准。安全页文案需在开发时按 AAS 公开要点逐条写就，不凭记忆编写（此为开发任务，本文档不定其内容）。
3. **读噪数据的来源与授权**：PhotonsToPhotos 数据为 Bill Claff 个人维护的公开实测站，个人自用场景下引用其数值并注明出处属常规做法；本 App 为个人侧载工具、不公开发行、不商用，风险低。若未来考虑公开分发，需重新评估数据授权并改以自测或获授权数据为准——此判断记入此处，MVP 不处理。
4. **经验口径的主观性**：严苛档位的系统推荐规则、深空总时长分档、广域 ISO 区间、第 6 节评分权重等含社区经验成分，不同流派数值可差一档上下；本文件已逐处标注「经验值 / 口径」。其中 NPF k 与 swamp C 已并入严苛三档体系（见第 5 节通则一）；评分权重在 v1.1 开发期以固定夜晚用例校准后写死，校准样本不足时宁可推迟完整版，不拿未校准权重充数。
5. **设备数据时效**：固件更新理论上可改变增益映射（A1 II 机械 / 电子快门切换点不同即为例证）；相机表带版本与日期，用户升级相机固件后若发现读噪行为变化，应回查数据表——App 设置页保留「数据版本与来源」查看入口。
6. **单人工具的维护风险**：无云端、无账号意味着换手机时数据迁移全靠本地导出；计划与设备库的一键导出 / 导入（JSON）已纳入 v1.0 作为兜底（见 7.3 / 9.1）——兜底的前提是用户记得在换机前导出，App 在设置页常驻该入口，不做任何自动云备份。
7. **日食本地接触时刻缺口（登记项）**：v1.0 的日食模块只有事件级预报 + 分阶段曝光参考，**不提供用户所在地的初亏 / 食甚 / 复圆时刻**（成因与排期见 5.4.2）。此缺口的安全相关性在于：摘镜时机依赖本地时刻，若界面有任何暗示「本地时刻已算出」的表述，用户可能据此误判——故文案边界写进 5.4.2 的设计要点，验收时逐屏检查。v1.1 自算落地时，ΔT 的不确定性（未来日期的 ΔT 只能外推）会给接触时刻带来秒至分钟级误差，须在结果旁标注。
8. **数据许可边界（登记项）**：光害数据 Falchi 图谱为 **CC BY-NC 4.0**——本 App 当前自用形态合规，但这条许可**锁死了未来的商业化路径**：一旦收费分发，必须先换数据源（自建 VIIRS 传播模型或购买商业图谱），不是补署名能解决的。深空 / 恒星数据（OpenNGC、HYG）为 **CC BY-SA 4.0**：自用不触发分发义务，但若对外分发 App 或衍生数据集，须署名且衍生数据以同许可开放。两项义务的执行动作（数据来源页）已写入 8.3；若分发方式变化，第 8.3 节选型结论整体重审。

## 附录 B：术语速览

- **NPF 法则**：由光圈（N）、像素间距（P）、焦距（F）算不跟踪时星点不拖线的最长快门。
- **像元角尺度**：一个像素对应的天空角度（″/px），= 206.265 × p / f。
- **双增益 / HCG 切换点**：传感器在某个 ISO 切换到高转换增益，读噪阶跃下降的那一档 ISO。
- **swamp（淹没读噪）**：让单帧背景天光电子数达到读噪平方的若干倍，使读噪在叠加后可忽略的曝光策略。
- **天文夜**：太阳低于地平线 −18° 的时段，完全无暮光影响。
- **Rs（日食）**：日冕距离以太阳半径为单位，0.5 Rs 指盘面外 0.5 个太阳半径处的内冕。
- **总天光**：光害基线（离线图谱 / 手动 Bortle 覆盖）与月光贡献在线性亮度域合成后的天光亮度，各模型的统一输入（见第 5 节通则二）。
- **严苛档位**：全局三档（严格 / 标准 / 宽松），统一决定拖线容忍、NPF 系数 k、swamp 系数 C 与背景目标位（见第 5 节通则一）。
- **ZHR（流星雨）**：天顶每小时辐射率——理想条件下（辐射点在天顶、无月光、极限星等 6.5）每小时可见流星数的标称量，实际观测恒低于此值。
- **辐射点**：同一场流星雨的流星轨迹反向延长后在天球上的交汇点，其高度决定当晚可见流星的多寡。
- **mpsas / SQM**：天光亮度单位 mag/arcsec²（每平方角秒星等），数值越大天越暗；SQM 亦指测量该量的 Sky Quality Meter 仪器读数。
