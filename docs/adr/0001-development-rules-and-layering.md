# ADR-0001: 采纳开发纪律与分层架构（DEVELOPMENT-RULES）

- 日期：2026-10-26
- 状态：Accepted

## 背景

本项目为开源项目、预期长期维护。长期维护的主要风险是代码腐化：第三方库直接侵入业务代码后，上游升级、替换或停更都会牵动全局；公式与数据若散落在多处实现，数值正确性无法持续验证。因此需要在动工之初就定下架构与流程约束，把「防腐化」写成可执行的规则，而不是事后补救。

## 决定

采纳仓库根目录 `DEVELOPMENT-RULES.md` 作为本项目的开发纪律，要点：

- **分层单向依赖**：UI → 用例 → 纯 Kotlin 领域层 → 端口接口 → 适配器，上层只依赖接口，不依赖实现。
- **第三方经接口层隔离**：历算、星表、光害图谱、食表、流星雨表等外部能力一律经命名端口接口（如 `EphemerisProvider`、`LightPollutionSource`）接入，DTO 转换只发生在适配器内；业务代码不直接引用第三方类型。
- **契约 + 金标准测试**：每个端口接口配契约测试与公开值金标准对照；升级第三方版本时，金标准测试文件不得在同一次提交中修改。
- **数据管线可复现**：光害网格、食表、星表等内置数据一律由 `scripts/` 下的脚本从原始来源生成并带 schema 版本，禁止手改生成物。
- **纯函数与单位纪律**：领域计算为纯函数、显式传入时间与位置；角度等量以带单位的值类型表达，弧度只出现在适配器边界。

## 后果

- 前期成本：一期需先搭分层骨架、端口接口与金标准测试，地基工作量高于直接堆功能。
- 升级流程约束：第三方版本升级须按「改适配器 → 跑契约与金标准测试 → 记录来源与版本」的流程执行，vendored 源码的改动须留补丁日志。
- 收益：上游更新只影响适配层，业务与领域代码零改动；数值结论可由金标准测试长期回归验证。
