# ADR-0004: 方向传感器经 DeviceOrientationProvider 端口接入

- 日期：2026-10-28
- 状态：Accepted

## 背景

0.8.0 的目标详情弹出窗新增实时指向：罗盘显示目标方位、竖直高度尺显示目标高度，手机姿态随转动实时跟随。方向与姿态数据来自设备传感器，这是本项目此前没有的外部依赖：读数带平台类型、带磁北口径、带精度档，且数值随设备与环境变化。若 UI 或领域层直接调用平台传感器 API，平台细节将穿透分层，磁偏角修正与精度口径也会散落多处（DEVELOPMENT-RULES A、B 节）。

## 决定

- **新增端口 `DeviceOrientationProvider`**，位于 `domain.orientation` 包，与既有端口同级。端口只用领域类型描述能力：订阅式接口，调用方传入地点与时刻后持续接收样本，返回的订阅句柄用于退订（开窗订阅、关窗退订）。
- **端口只出真北口径值**：样本的朝向为真北口径角度（度），同时给出手机顶边指向的仰角、屏幕法线倾角与显式精度档 `OrientationAccuracy`（HIGH / MEDIUM / LOW / UNRELIABLE）；不可用以 `isAvailable()` 显式表达，流中断以样本停发呈现，不用 null、-1 一类魔法值表达失败（DEVELOPMENT-RULES E.5）。
- **适配器落在 app 模块，为端口的唯一实现处**：平台 `SensorManager` 的 `TYPE_ROTATION_VECTOR` 优先，无该传感器时回退加速度计与磁力计组合；旋转矩阵换算、低通平滑与精度档映射均止于适配层。
- **磁偏角修正落适配层**：适配层按调用方传入的地点经纬度、海拔与日期，调平台 `GeomagneticField` 得磁偏角并加到磁朝向得真北；domain 与 UI 不接触磁偏角与平台类。
- **阈值与状态机为 domain 纯函数**：带符号方位角差、高度差、对准状态机（双轴独立滞回）与平放判定均为纯 Kotlin 函数，显式入参、可单测；阈值常数集中定义并注明出处类别。指向的目标方位与高度仍来自现行评估入口，端口不新增历算路径。
- **不新增权限、不联网**：方向与姿态传感器不在运行时权限清单内，采样率低于高采样率权限门槛，Manifest 权限集合维持现状；磁偏角由平台内置地磁模型离线计算。

## 后果

- 真机姿态数值不可在 JVM 复现：契约测试只钉端口的消费语义（以假适配器喂已知样本序列，断言用例与 domain 对样本的消费和状态迁移），不在契约中伪造真机真值；真机验证另列清单（真北对照、磁干扰场景、平放与竖持切换、对准滞回手感、红光下可读性），随 0.8.0 开发批执行。
- 无罗盘类设备走静态降级：`isAvailable()` 为假时指向区整卡替换为目标方位与高度的静态数值呈现，其余各区不受影响。
- 不采纳 `uses-feature android.hardware.sensor.compass` 声明：运行时降级已覆盖无罗盘设备的呈现与可用性，清单声明对安装与运行无实际作用，不为其增加一处需要长期维护的声明。
- 上游变化面收敛于适配层：平台传感器行为或融合方式变化时，只改 app 模块适配器与契约测试，domain、UI 与历算口径不变。
- **选型调研结论（2026-10-28，docs/compass-survey.md）**：不引入任何罗盘 / 融合库。融合、真北修正与精度档三块重活均为平台自带，库可替代的只有适配层接线量级。自研适配层借鉴两处已验证的做法（出处与许可证标注在适配器注释中）：Andromeda `sense`（MIT，Kyle Corry）的真北处理形态（平台旋转矩阵 + `GeomagneticField` 磁偏角在适配层内修正、端口只出真北值），与 Trail-Sense（MIT，同作者）「靠近金属时上报更低罗盘精度」的做法（适配层以磁场总强度越界判定降级一档）。**FSensor（Apache-2.0）留作同端口可换备选**：它以自研融合替换平台融合，但不处理磁偏角与精度语义，与本端口要解决的问题不对口，本批不引入；仅当真机验证发现目标设备平台融合明显不佳时，才在同一端口后以 FSensor 适配器替换，domain 与 UI 不动。Stardroid v2、Stellarium、KStars 均为 GPL，与本仓 MIT 不相容，代码不并入；Stardroid v1（Apache-2.0）仅作经验阅读。
