# Data pipelines

All bundled catalogue data under `data/src/main/resources/catalog/` is
generated by the scripts in this directory from public sources (see
[../DATA-LICENSES.md](../DATA-LICENSES.md) and
[data-sources.md](data-sources.md)). Generated files must never be edited
by hand: change the script or its inputs, re-run, and commit script +
output together.

Common rules:

- Raw downloads are cached in `scripts/.cache/` (git-ignored) and reused
  on re-runs.
- Outputs are deterministic: stable sort order, no timestamps inside the
  data body; retrieval dates live only in the `dataVersion` field.
- Every script asserts its minimum counts and golden checks and exits
  non-zero when they fail.
- Python dependencies beyond the standard library: `requests` (HTTP),
  `pypdf` (IMO calendar parsing), `tifffile` + `numpy` (Falchi GeoTIFF
  resampling, only needed for the full-atlas path).

## build_objects.py — deep-sky objects

- Source: OpenNGC `NGC.csv` + `addendum.csv` (CC BY-SA 4.0).
- Command: `python3 scripts/build_objects.py`
- Output: `data/src/main/resources/catalog/objects.json`
- Content: all 110 Messier objects (M102 taken as NGC 5866, see script
  header) plus bright NGC/IC deep-sky objects (galaxies mag <= 10.0,
  clusters/nebulae mag <= 10.5), 576 objects total at build time.
- Data version record: `dataVersion` field in objects.json +
  [data-sources.md](data-sources.md).

## build_eclipses.py — solar / lunar eclipses 2026-2035

- Source: NASA GSFC Eclipse Web Site decade catalogues (Espenak & Meeus),
  supplemented by the Five Millennium Canon century catalogues on the
  same site for path width (solar) and penumbral magnitude (lunar).
- Command: `python3 scripts/build_eclipses.py`
- Output: `data/src/main/resources/catalog/eclipses.json`
- Data version record: `dataVersion` field in eclipses.json +
  [data-sources.md](data-sources.md).

## build_showers.py — meteor showers

- Source: IMO Meteor Shower Calendar 2026 (Working List, Table 5; radiant
  drift derived from Table 6), IMO. The IMO working-list web page is a
  JavaScript application shell with no embedded data rows, so the
  calendar PDF from imo.net is the parsed source instead.
- Command: `python3 scripts/build_showers.py`
- Output: `data/src/main/resources/catalog/showers.json`
- Data version record: `dataVersion` field in showers.json +
  [data-sources.md](data-sources.md).

## build_lenses.py — built-in lens list

- Source: manufacturer lens line-ups (Sony E, Canon RF, Nikon Z, Tamron,
  Sigma), curated at build time in the script; only models whose mount,
  focal length and maximum aperture are firmly established are included.
- Command: `python3 scripts/build_lenses.py`
- Output: `data/src/main/resources/catalog/lenses.json`
- Schema note: variable-aperture zooms carry an extra optional field
  `maxApertureTele` (maximum aperture at the telephoto end, e.g. 2.8 for
  the Tamron 35-150mm F2-2.8 in the list below); constant-aperture zooms and primes omit it.
- Data version record: `dataVersion` field in lenses.json +
  [data-sources.md](data-sources.md).

## fetch_falchi.py + resample_falchi.py — light-pollution grid

- Source: Falchi et al. 2016 World Atlas (CC BY-NC 4.0), DOI
  10.5880/GFZ.1.4.2016.001.
- Commands: `python3 scripts/fetch_falchi.py` (resumable download of
  World_Atlas_2015.zip from the GFZ datapub direct link, TIFF
  extraction + SHA-256 provenance),
  `python3 scripts/resample_falchi.py` (GeoTIFF -> full grid; the
  sparse sample grid fallback described in the script header applies
  only when no GeoTIFF is present in the pipeline cache).
- Output: `data/src/main/resources/catalog/lp-grid.bin`
- Data version record: header JSON inside lp-grid.bin +
  [data-sources.md](data-sources.md).
