# TEST FIXTURE — catalogue contract-test data

Everything in this directory is a **TEST FIXTURE**, not production data.
It exists so the catalogue contract tests in
`data/src/test/kotlin/app/astroexposure/data/catalog/` can run against the
port interfaces before the build-time data pipelines deliver the real
products into `data/src/main/resources/catalog/`. When the real products
land, the same contract tests must be re-run against them unchanged by
the integrating change.

Fixture facts asserted by the tests:

- `objects.json` — M31 (raHours 0.712, decDeg 41.269, magnitude 3.4,
  type GALAXY), M42 (NEBULA), M45 (CLUSTER_OPEN), M13 (CLUSTER_GLOBULAR).
  Coordinates and magnitudes are the well-known catalogue values for
  these Messier objects, rounded to 3 decimals.
- `eclipses.json` — the four 2026 events of the NASA GSFC catalogue
  (Espenak & Meeus): 2026-02-17 annular solar, 2026-03-03 total lunar,
  2026-08-12 total solar, 2026-08-28 partial lunar. Peak times and
  magnitudes are rounded fixture values, not pipeline output.
- `showers.json` — PER (peakLon 140.0, peakZhr 100) and GEM, with
  IMO-style fields at fixture precision.
- `lenses.json` — Sony FE 50mm F1.4 GM (prime, `maxApertureTele`
  absent) and a Tamron 28-200mm variable-aperture zoom
  (`maxApertureTele` 5.6).
- `lp-grid.bin` — hand-built light-pollution grid, regenerated by the
  committed `generate_lp_fixture.py` (run it in this directory). Two
  grids: a coarse one (step 5.0, scale 0.5, one 0xFFFF no-data cell) and
  a finer one inside it (step 1.0, scale 0.25) whose New York cell
  (40.7128, -74.0060) stores raw 800 = 200.0 mcd/m² and whose
  (row 0, col 1) cell is 0xFFFF to exercise the coarse fallback.

- `lp-grid-full.bin` / `lp-grid-sparse.bin` — header-form variants
  written by the same generator: one tiny grid each, with the header
  fields the data pipeline writes for the full atlas (`gridKind`
  `"full-grid"`, `dataVersion` ending in `(resampled 2026-10-27)`) and
  for the sparse sample grid (`gridKind` `"sparse-sample"`,
  `dataVersion` ending in `on 2026-09-30`). They pin the structured
  `versionInfo` parsing behind the location card's short display.

All fixture documents carry `"dataVersion": "test-fixture-1"` unless a
variant header above says otherwise.
